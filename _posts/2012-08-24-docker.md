## Docker glossary:

- <strong>image</strong>: a read-only template with instructions for creating a Docker container

- <strong>container</strong>: a runnable instance of an image. You can create, start, stop, move, or delete a container using the Docker API or CLI

- <strong>volume</strong>: persists data generated by and used by Docker containers

- <strong>dangling</strong>: unused image or volume

- <strong>network</strong>: connects Docker containers and services

- <strong>node</strong>: an individual Docker Engine instance in a Swarm 

Three Linux Kernel technologies enable Docker:

- <strong>Namespaces</strong> isolate resources from each other: processes, network interfaces, IPC (InterProcess Communication), disk mount points, UTS (Unix Timesharing System), etc. Namespaces were first introduced in 1973 when <tt>syscall chroot()</tt> was added to UNIX<a target="_blank" href="https://www.slideshare.net/slideshow/embed_code/key/16wAuaVKga8tib">*</a>. "change root" made it such that a program running in the chroot environment has its own root catalog of folders (bin, sys, lib, etc.).

- <strong>Control groups</strong> control resources consumed by each process group by prioritizing, measuring usage, and freezing groups of processes.

- <strong>Union File System</strong> begins with a base image of (overlays) branches (layers) of file changes merged. Branches can be read-only or read-write.

## Docker Certified Associate (DCA) exam

The real (remote) exam is to answer 60% of 55 English multiple-choice questions in 90 minutes.

PROTIP: Take sample exams for a humbling experience, so you get an accurate sense of how prepared you really are.

PROTIP: Take sample exams several times until you answer all questions for a 100% score. 
This is not a waste of time because most questions people get wrong are due to <strong>misreading</strong> rather than lack of knowledge. So you retrain your "muscle memory" like learning to type some words you always type incorrectly.

It costs $195 to <a target="_blank" href="https://prod.examity.com/docker/">Examity</a> for a two year badge. Phone Support: 855-392-6489.

## Swarm Mode

Many use Docker with <a target="_blank" href="https://wilsonmar.github.io/kubernetes">Kubernetes</a> rather than Docker's own Swarm.
But it's Docker's exam, so there are questions about Swarm Mode.

   Docker Enterprise nodes can be run by both Kubernetes and Docker Swarm in parallel.

Docker EE signs and scans Kubernetes apps as part of policies auto promoting apps.

## Enterprise features

https://docs.docker.com/ee/

> PROTIP: Most tutorials don't cover Enterprise features Docker's licensed <a target="_blank" href="https://www.docker.com/products/docker-enterprise">Enterprise Edition (EE)</a> documented at <a target="_blank" href="https://docs.docker.com/ee/">https://docs.docker.com/ee</a>. Nevertheless, the DCA exam includes questions about additional enterprise features for businesses wanting a secure and supported container platform for their datacenter:

   * Vulnerability scans 
   * Notary

   * Version Packs in Desktop Enterprise to keep the client in sync (v 3.0 vs. 2.1)
   * <a target="_blank" href="https://docs.docker.com/app/working-with-app/">>docker app</a> packaging command to install clients in swarm or kubernetes according to the vendor-neutral <a target="_blank" href="https://cnab.io/">"Cloud Native Application Bundle" (CNAB) spec</a> at <a target="_blank" href="https://github.com/deislabs/cnab-spec">https://github.com/deislabs/cnab-spec</a>

   * <tt>docker cluster</tt> command to create, ls, backup, restore clusters as code on AWS, Azure, and VSphere
   * Docker Kubernetes Service support of all Docker Enterprise features such as<br /><tt>docker stack deploy</tt>
   * <a target="_blank" href="https://docs.docker.com/engine/context/working-with-contexts/">docker context</a> enable a single Docker CLI to switch among multiple contexts of Swarm clusters,  Kubernetes clusters, and individual Docker nodes.
   * <a target="_blank" href="https://docs.docker.com/app-template/working-with-template/">docker template</a>
   * <a target="_blank" href="https://docs.docker.com/buildx/working-with-buildx/">docker buildx</a> CLI plugin extends the docker command with features in the Moby BuildKit builder toolkit, such as creating scoped builder instances and building against multiple nodes concurrently.
   * <a target="_blank" href="https://docs.docker.com/assemble/install/">docker assemble</a> (experimental) to build without Dockerfileby detecting Spring Boot and ASP.NET Core.
   <br /><br />

> Docker Enterprise hosted trials at <a target="_blank" href="https://trial.docker.com/">trial.docker.com</a> last only 12 hours.  https://trial.docker.com/demo has these menu itmes:

* <strong>Admin Console</strong> is a command-line terminal to the cluster. In it, directly run commands to deploy and manage applications. Run <tt>docker info</tt> to check the status of the cluster.

* <strong>Universal Control Plane</strong> (UCP)
   is a web interface to deploy and monitor applications across machines (as a cluster).
   See <a target="_blank" href="https://docs.docker.com/ucp/">
   https://docs.docker.com/ucp</a>

   <a target="_blank" href="https://user-images.githubusercontent.com/300046/62816894-52c16e00-baeb-11e9-8469-7042b9061344.jpg"><img alt="docker-ucp-samp-1010x621.jpg" src="https://user-images.githubusercontent.com/300046/62816894-52c16e00-baeb-11e9-8469-7042b9061344.jpg"></a>

* <strong>Docker Trusted Registry</strong> (DTR) is a more secure DockerHub to host vetted Docker images, adding reports about scans for vulnerabilities. See <a target="_blank" href="https://www.docker.com/products/docker-trusted-registry">https://www.docker.com/products/docker-trusted-registry</a>.

   Examples to pull down an image from it:

   <pre><strong>docker pull my-registry.net:5000/activemq
docker pull 06c482d5-2c1a-48c2-a28c-6f3e53f3dde5.dtr.dockertrial.com/example/tomcat
   </strong></pre>

   DTR holds digital signatures of apps by specific team members with <a target="_blank" href="https://docs.docker.com/engine/security/trust/content_trust/">Docker Content Trust</a> policy enforcement.
   See <a target="_blank" href="https://docs.docker.com/registry">https://docs.docker.com/registry</a>.

   DTR was an early adopter of the <a target="_blank" href="https://github.com/theupdateframework/specification/blob/master/tuf-spec.md">TUF ("The Update Framework") specification</a> TAPS:

   TAP 3: Multi Role Delegations uses multiple keys and require a threshold quorum for action to minimize compromise. Roles are specific:

   * 
   
   TAP 4: Multiple Repository Consensus on entrusted targets

   TAP 6: Include specification version in metadata

   TAP 9: Mandatory Metadata signing schemes

   TAP 10: Remove native support for compressed metadata

   
   <a target="_blank" href="https://en.wikipedia.org/wiki/The_Update_Framework_(TUF">"compromise-resilience"</a> which limits the impact of attacks and provide a mechanism for recovery even if the software repository becomes compromised.

   open-sourced by the Linux Foundation.
