Kafka is an Apache project at https://kafka.apache.org/

Being Apache, it's open source, <a target="_blank" href="https://cwiki.apache.org/confluence/display/KAFKA/Clients">used by many clients</a>. <a target="_blank" href="https://engineering.linkedin.com/blog/2016/04/kafka-ecosystem-at-linkedin">LinkedIn</a> and <a target="_blank" href="https://medium.com/netflix-techblog/kafka-inside-keystone-pipeline-dd5aeabaf6bb">Netflix</a> have publicly blogged about their use of Kafka for data collection and buffering for downstream systems like Elasticsearch, Amazon EMR, Mantis etc.

Kafka provides scalable <strong>stream</strong> processing applications that react to events in real-time.

Kafka sits as a "broker" between
"Producers" generating event logs, monitoring data, suspicious user actions, etc. 
and "consumers" of services, much like a messaging system (RabbitMQ, etc.).

Kafka stores streams of data safely in a distributed, replicated, fault-tolerant cluster.

In other words, Kafka is a hybrid of a distributed database and a message queue.

The logo for Kafka is the Greek Lambda letter.
"Lambda Architecture" is a data processing architecture and framework designed to address robustness of the scalability and fault-tolerance (human and machine) of big data systems.
The lambda symbol has two legs.
To a traditional batch layer processing master data is added
a speed layer using Spark streaming.
These communicate with a Serving layer.

## Simulated traffic

Measurement of performance under load is important to quantify known risks:

1. Kafka has a long message storing time (a week, by default), so what is the rate of disk space usage? How much disk space is needed based on projections of usage? Are mechanisms for clearing and managing disk and alerting about additional space adequate? 
1. Kafka was designed for high performance with its sequential I/O. But what is the capacity?
1. Kafka can transfer data quickly, but at what sustained rate can Kafka process it by using Streaming API.
1. Kafka makes clustering convenient to achieve "HA" (high availability). But how many nodes are adequate? 
1. How long does it take for traffic to a failed node to be replicated and distributed across the cluster?
1. How does the system detect a denial of service attack? Can it really? And how quickly?

Unlike traditional web sites,
Kafka reads and writes <strong>streams</strong> of data.
