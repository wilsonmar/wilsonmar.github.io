This tutorial describes the different options to <a name="Install">install</a>, <a href="#Uninstall">uninstall</a>, configure, and use various versions of Python with its various packages, all running in a virtual enviornment also managed by pyenv.

In this article I take a carefully crafted narrated tour. Here is a hands-on "deep dive" tutorial so you better grasp the complexities in a shorter time. Why? Because I haven't seen one on the internet. 

I thank the other authors on StackOverlow and elsewhere.


<a name="Python2"></a>

## System Python2 

   Although macOS comes with the "System" version of Python, it is Python2, which is obsolete.

1. Get a list of the various locations where Python is installed:

   <pre><strong>type -a python
   </strong></pre>

   The response may show Python being installed in several locations:

   <pre>python is /usr/bin/python
   </pre>

   The <tt>/usr/bin/</tt> folder is owned by the operating system, so sudo is required to modify files in it (such as "python").

1. That path returned is shown:

   <pre><strong>which python
   </strong></pre>

   The "python" in the path "/usr/bin/python" is actually a <strong>symbolic link</strong> to the actual executable.

1. List symbolic link "/usr/bin/python": 

   <pre><strong>ls -l /usr/bin/python
   </strong></pre> 
   
   Response:

   <pre>lrwxr-xr-x  1 root  wheel  75 Apr 15 03:55 /usr/bin/python -> ../../System/Library/Frameworks/Python.framework/Versions/2.7/bin/python2.7
   </pre>

   The "../../" above means that it's above your HOME folder, in the root of the Mac OS.

1. So let's see what files are there:
 
   <pre><strong>ls /System/Library/Frameworks/Python.framework/Versions/2.7/bin/
   </strong></pre>

   Listed are executables "python", "python2", and "python2.7", plus others.


   ### View $PATH

1. View the contents of the $PATH variable to see if it includes "/usr/bin/python":

   <pre><strong>echo $PATH</strong></pre>

   If that's too much, view it in a file by a text editor:

   <pre>echo "$PATH" >path.txt
   edit path.txt
   rm path.txt
   </pre>

1. If it's listed, invoke the program to get the version number:

   <pre><strong>python2 --version</strong></pre>

   On a MacOS Catalina version operating system, you would see:

   <pre>Python 2.7.16</pre>

1. The version is also returned from:

   <pre><strong>python2 -V</strong></pre>

Python 2 reached <a target="_blank" href="https://opensource.com/article/19/11/end-of-life-python-2">end of life</a> in January 2020.


<a name="InstallPython3"></a>

## Ways to Install Python3

The Python3 interpreter is the default Python now, but it needs to be installed.

Python can be installed by various installers. 

   NOTE: The Azure CLI installs the version of Python it uses at:

   <ul><pre>/usr/local/opt/python@3.8/bin/python3
   </pre></ul>

PROTIP: Before installing things, first see what is already installed.

1. Get a list of the various locations where Python3 is installed:

   <pre><strong>type -a python3
   </strong></pre>

   The response may show Python being installed in several locations:

   <pre>python3 is /usr/bin/python3
python3 is /usr/local/bin/python3
python3 is /usr/local/opt/python@3.8/bin/python3
python3 is /usr/local/bin/python3
python3 is /usr/bin/python3
   </pre>

   PROTIP: There may be several Python executables installed in different folders. But the Python program actually executed is the first one that the operating system finds among folders defined in <a href="#PATH-edit">your PATH</a> system variable defined in <tt>~/.bash_profile</tt> or ~/.zshenv. The operating system searches for executables in each folder in the PATH, from left to right.

   Before pyenv, people define what version of "python" is executed by editing the PATH variable -- putting the path to Python3 executables before Python2 in $PATH. To have Python3 execute instead of Python2:

   <pre>export PATH="/usr/local/python3:$PATH"</pre>

   (Colon characters separate folders in the PATH)

   Also, Azure recommends this line at the bottom of <tt>~/.bash_profile</tt> files:

   <pre>export PATH="/usr/local/opt/python@3.8/bin:$PATH"</pre>


   ### Don't alias

   Some add aliases within the <tt>~/.bash_profile</tt> or ~/.zshenv file:

   <pre>alias python=python3
   alias pip=pip3</pre>

   But don't do that when you're using pyenv, which makes use of shims.


   <a name="WhatAreShims"></a>

   ### Pyenv shims

   You are good to go with Pipenv if you see in the response:

   <pre>python3 is /Users/wilson_mar/.pyenv/shims/python3
python3 is /usr/local/bin/python3
   </pre>

   (Instead of "wilson_mar", you'll see your own user name)

   The value of pyenv is:

   * Install Python in your user space
   * Install multiple versions of Python
   * Specify the exact Python version you want
   * Switch between installed versions

   ### Behind the magic of pyenv

   Pyenv enables switching among multiple versions of Python2 or Python3.

   The "magic" behind pyenv is a technique called <strong>"rehashing"</strong>.
   
   Commands for the operating system to execute "python3" are <strong>intercepted</strong> by a <strong>shim</strong> executable which passes your commands along to the actual Python installation of the desired version.

   That's achieved by setting the shim programs to be the first folder in <a href="#PATH-edit">your PATH</a> because the operating system searches for executables in folders in the PATH from left to right.


   <a name="PATH-edit"></a>

   ## Edit PATH 

1. Edit your <tt>~/.bash_profile</tt> or ~/.zshenv file so that the PATH comes before "/usr/local/bin" and "/usr/bin" where others install programs:

   <pre>export PATH="$(pyenv root):$PATH"
   </pre>

   Alternately, if you don't want to mess with a text editor, use this command:

   <pre>echo 'export PATH="$(pyenv root)/bin:$PATH"' >> ~/.bash_profile
   </pre>

   Alternately, since "pyenv root" is not likely to change:

   <pre>export PYENV_ROOT=$(pyenv root)
export PATH="$PYENV_ROOT/bin:$PATH"
   </pre>

   Instead of .bash_profile, specify ~/.zshrc or ~/.bashrc (for Ubuntu/Fedora).

   <pre>$(pyenv root)/shims:/usr/local/bin:/usr/bin:/bin
   </pre>

   (Colon characters separate folders in the PATH)

1. If you edited your shell, restart your shell terminal so the path changes take effect:

   <pre><strong>exec "$SHELL"
   source ~/.bash_profile</strong></pre>
   or ~/.zshrc
   
1. Verify:

   <pre>echo "$PATH" >path.txt
   edit path.txt
   rm path.txt
   </pre>

1. If you edited your shell, restart your shell terminal so the path changes take effect:

   <pre><strong>which python</strong></pre>

   Response should be:

   <pre>/Users/wilson_mar/.pyenv/shims/python</pre>
   
   ("wilson_mar" would be replaced with your user name)

   ## Order of Path override

   When a shim (such as "python") is executed, it calls pyenv which determines which Python release to use by reading sources in this order:

   1. $PYENV_VERSION
   2. pyenv local x.y.z
   3. pygenv global
   <br /><br />

   The <tt>PYENV_VERSION</tt> environment variable overrides all other specifications. 
   
1. Set this environment variable in your current shell session using the pyenv shell command.

   If the PYENV_VERSION system variable is not specified, the application-specific <tt>.python-version</tt> file in the <strong>current directory</strong>. 
   
1. Modify the current directory's .python-version file with the command:

   <pre><strong>pyenv local 2.7.15</strong></path>

   If there is no <tt>.python-version</tt> file locally, parent directories are searched upward until reaching the root of your filesystem.

   If no .python-version is specified in any folder, the global $(pyenv root)/version file. 
   
1. Modify the global file using the command:

   <pre><strong>pyenv global 3.7.7</strong></pre>
   
   If the global version file is not present, pyenv assumes you want to use the "system" Python. (In other words, whatever version would run if pyenv weren't in your PATH.)

## Virtual Environments #

   pyenv copies an entire Python installation every time a new pyenv version is created.

   By contrast, virtualenv makes use of symbolic links, which decreases the size of each virtualenv. 

   There are two utilities to add virtualenv functionality to pyenv: 
   <a target="_blank" href="https://github.com/pyenv/pyenv-virtualenvwrapper">pyenv-virtualenvwrapper</a>
   (described by
   https://alysivji.github.io/setting-up-pyenv-virtualenvwrapper.html)
   is less convenient and has less stars than the pyenv-virtualenv plugin. 
   To install it:

   <pre><strong>brew install pyenv-virtualenv
   </strong></pre>
   
   Alternately: 
   <pre><strong>git clone <a target="_blank" href="https://github.com/pyenv/pyenv-virtualenv">https://github.com/pyenv/pyenv-virtualenv.git</a> \
   $(pyenv root)/plugins/pyenv-virtualenv
source ~/.bashrc
   </strong></pre>

   The response:

   <pre>Cloning into '/Users/wilson_mar/.pyenv/plugins/pyenv-virtualenv'...
remote: Enumerating objects: 2064, done.
remote: Total 2064 (delta 0), reused 0 (delta 0), pack-reused 2064
Receiving objects: 100% (2064/2064), 580.31 KiB | 30.00 KiB/s, done.
Resolving deltas: 100% (1413/1413), done.
   </pre>

   This is needed because Virtualenv and Anaconda also activate scripts by mutating $PATH variable of user's interactive shell, which intercepts pyenv's shim style command execution hooks. 

   To automatically activate/deactivate virtualenvs on entering/leaving directories which contain a .python-version file that contains the name of a valid virtual environment as shown in the output of pyenv virtualenvs

   <tt>echo 'eval "$(pyenv virtualenv-init -)"' >> ~/.bash_profile</tt>
   or <tt>~/.zshrc</tt>

1. List what virtualenv has been defined

   <pre><strong>pyenv virtualenvs
   </strong></pre>

1. List what virtualenv have been defined:

   <pre><strong>pyenv virtualenvs
   </strong></pre>

   There are several ways to enter and setup a virtual environment:

1. Set up a virtual environment in the present working directory:

   <pre><strong>python -m venv venv</strong></pre>

   No response is returned if it's all good.
   
   But a virtual folder named after the project is created.

   To deactivate, type:

   <pre><strong>exit</strong></pre>

2. Alternately, to activate virtualenv, run 
   
   <pre><strong>pipenv shell</strong></pip>

3. Alternatively, run a command inside the virtualenv 
   
   <pre><strong>pipenv run
   </strong></pre>

1. Activate the virtual environment in the present working directory:

   <pre><strong>source ./venv/bin/activate</strong></pre>

   This would turn the command prompt as a constant reminder:

   <tt>(venv)</tt>
   
1. which python

   /Users/... my_project/venv/bin/python



   ## Pipfile.lock

   The <tt>Pipfile.lock</tt> file contains a hash of each package installed,
   which provides security. 
   The file pins semantic versions of all dependencies and sub-dependencies, which provides replicable environments.
