<a target="_blank" href="https://wilsonmar.github.io/tricentis-flood/">This article</a> is a hands-on, step-by-step deep-dive tutorial about load testing SAP Fiori 3 sample apps using Flood.io Elements. We setup the scripts to run automatically when changes to a sample app is pushed into a GitHub repo. Covered are setup and interpretation of APM (Application Performance Monitoring) metrics about application health. Results of light load tests trigger an email alert if anomalies are identified.

1. If you don't have a Google Chrome Browser app installed, please install it because end users use the Google Chrome browser to run SAP Fiori v3 apps online over the internet.

2. If you are not using Chrome to view this page, triple-click the URL below to copy the URL, then switch to the Chrome browser and paste this page's address in the address field:

   <a target="_blank" href="https://wilsonmar.github.io/sap-fiori">https://wilsonmar.github.io/sap-fiori</a>
   
3. The menu of small apps which SAP created to demonstrate SAP Fiori v3 UI technology is at:

   <a target="_blank" href="https://sapui5.hana.ondemand.com/#/demoapps">https://sapui5.hana.ondemand.com/#/demoapps</a>

4. Learn to automate manual actions into Flood Element TypeScript using Google Chrome Developer Tools:

   <a target="_blank" href="https://wilsonmar.github.io/flood-coding">https://wilsonmar.github.io/flood-coding</a>

5. Now dive in. For each app in the menu <a href="#DemoGUIApps">listed below</a>:

   Click <a target="_blank" href="https://sapui5.hana.ondemand.com/#/demoapps"><img width="21" src="https://user-images.githubusercontent.com/300046/60136601-daccfd80-9761-11e9-8641-3bd7489f0afd.png"></a> to see the GUI of each SAP Fiori v3 demo app which <a target="_blank" href="https://sapui5.hana.ondemand.com/#/topic/a3ab54ecf7ac493b91904beb2095d208">exhibit use of certain features, layouts, or component</a>.<br />

   Click <img width="21" alt="User manual actions icon-doublecheck-21x21.jpg" src="https://user-images.githubusercontent.com/300046/62120133-41bc6580-b27e-11e9-88e2-7d5a21ab74a6.jpg"> to see a textual list/description of user actions on that app and how those actions are coded for automation.<br />

## Why perftest a cloud app?

Speed performance (productivity of users) is claimed as a key advantage for moving to SAP Fiori.

<a target="_blank" href="https://sapui5.hana.ondemand.com/"><img alt="sap-evolution_demokit-835x400-25263.png" width="835" src="https://user-images.githubusercontent.com/300046/57400342-7beefd00-7190-11e9-91bc-16f4b0d400ad.png"></a>

Traditional JMeter Java or LoadRunner C scripts were designed to mimic the exchange of <strong>static</strong> HTML between user client and web server. Such client programs pretend to be hundreds of actual users on a single server because it generates requests but does not do much with responses from web servers.

Web apps are built for users who access internet browsers such a Google Chrome.

But "modern" apps are built using UI framework libraries such as Angular, React, Vue.
Such frameworks have JavaScript perform actions that operate within user client browser programs that <strong>dynamically</strong> alter the HTML and CSS processed by the browser.

Traditional scripts require custom coding to process ASP.NET apps which exchanged an "ACTIVE STATE" containing instructions on how forms are processed. Such complications can be avoided when crafting scripts that focus on browser JavaScript rather than interpreting HTML protocol.

Flood.io can run scripts written to run using JMeter and Gatling which read HTTP.
