Airflow is a platform to programmatically author, schedule, and monitor <strong>workflows</strong> to process data where output of one element is the input of the next element.

A "data workflow" is a sequence of tasks which begin by a triggering event.

The Airflow scheduler executes tasks on an array of workers while following specified dependencies. 

Use Airflow to author workflows as DAGs (Directed Acyclic Graphs) of tasks (named t1, t2, etc.). 

   * "Directed" meaning sequenced
   * "Acyclic" meaning flow is one-way
   * https://www.youtube.com/watch?v=XD7euLOzKbs
   <br /><br />

Airflow instantiates pipelines dynamically.

https://www.youtube.com/watch?v=l764YAGPlIs
Scalable Data Ingestion Architecture Using Airflow and Spark | Komodo Health
Data Council

When workflows are defined as code so they become more maintainable, versionable, testable, and collaborative.

Airflow uses operators for working with Python, Postgres, Bash, Email, etc.

Airflow pipelines are lean and explicit. Parameterizing your scripts is built into the core of Airflow using the powerful <a target="_blank" href="https://jinja.palletsprojects.com/en/2.11.x/">Jinja templating engine</a>.

Rich command line utilities make performing complex <strong>surgeries</strong> on DAGs a snap. 

A rich user interface makes it easy to visualize pipelines running in production, monitor progress, and troubleshoot issues when needed.

Airflow is commonly used to process data, but has the opinion that tasks should ideally be <strong>idempotent</strong> (i.e., results of the task will be the same, and will not create duplicated data in a destination system).

Airflow is not designed to pass large quantities of data from one task to the next (though tasks can pass metadata using Airflow's Xcom feature). 

For high-volume, data-intensive tasks, a best practice is to delegate to external services specializing in that type of work.

1. Create <tt>airflow</tt> folder under the root folder:

   <pre>mkdir -p $HOME/airflow/dags
   </pre>

1. Define the path as the <strong>AIRFLOW_HOME</strong> environment variable in ~/.bash_profile

   <pre>export AIRFLOW_HOME=$HOME/airflow-tutorial
   cd "$AIRFLOW_HOME
   </pre>

1. Airflow is installed in <tt>~/.local/bin</tt> so in .bash_profile:

   <pre>PATH=$PATH:~/.local/bin
   ls ~/.local/bin
   </pre>

   WARNING: <tt>brew info airflow</tt> refers to a video watching app for AppleTV.

### Tasks

Python bit-wise operators are used to specify dependencies:

   <pre>   first_task >> [second_task, third_task]
   third_task &LT;&LT; fourth_task
   </pre>

Alternately, use the more explicit set_upstream and set_downstream methods:

first_task.set_downstream(second_task, third_task)
third_task.set_upstream(fourth_task)
