SIEM is an industry-wide term. According to Gartner [1]

> Security information and event management (SIEM) technology supports threat detection, compliance, and security incident management through the collection and analysis (both near real time and historical) of security events, as well as a wide variety of other event and contextual data sources. The core capabilities are a broad scope of log event collection and management, the ability to analyze log events and other data across disparate sources, and operational capabilities (such as incident management, dashboards, and reporting).

{% include whatever.html %}

SIEM provides for analysis of security <strong>alerts</strong> based on log and event data generated by applications and network hardware (usually globally)
in order to give <strong>centralized security teams</strong> the insight to detect and analyze advanced threats.

> SIEM is a security solution that helps organizations recognize potential security threats and vulnerabilities before they have a chance to disrupt business operations. -- IBM

"Legacy" SIEM has been around since 2005, but has evolved significantly since then from just log management. SIEMs were known for their blind spot on unstructured data and emails. For example, you might see a rise in network activity from an IP address, but not the user that created that traffic or which files were accessed.

Not anymore.

SIEM software combines Security Information Management (SIM) and Security Event Management (SEM). 
Its processes include data aggregation, event correlation, alerting, dashboards, compliance, retention, and forensic analysis.

1. <strong>Collect</strong> data from various sources (network devices, servers, domain controllers, etc.)

   SIEM gathers data from antivirus events, firewall logs, and other locations.

2. Normalize and <strong>aggregate</strong> collected data so it can be analyzed

3. Identify and categorize incidents (as sessions) to detect <strong>threats</strong>

   SIEM sorts this data into categories, for example: malware activity and failed and successful logins. When SIEM identifies a threat through network security monitoring, it generates an alert and defines a threat level based on predetermined rules. For example, someone trying to log into an account 10 times in 10 minutes is ok, while 100 times in 10 minutes might be flagged as an attempted attack.

4. Pinpoint security breaches and enable organizations to <strong>investigate</strong> generated alerts (forensics analysis)

   SIEM software matches events against <strong>rules</strong> in analytics engines which <strong>indexes</strong> logs to enable searches and <strong>event correlation</strong>.

5. <strong>Respond</strong> to incidents automatically and manually (using <a href="#SOAR">SOAR</a> software to apply automation and structure manual procedures defined in "playbooks").


## SOAR

Security Orchestration, Automation, and Response (SOAR) systems help reduce response times by prioritizing real threats.
SOAR tools allow an organization to define incident analysis and response procedures in a digital workflow format.
SOAR automates workflows and accelerates threat qualification, investigation, and response. 

SOAR tools can be integrated with SIEM tools to automate incident response workflows:
Bash Shell scripts, Python, and other languages.


## Used by SOC teams

A corporate-wide Security Operations Center (SOC) typically owns the operation of SIEM/SOAR systems.
This team reports to the Chief Information Security Officer (CISO) or Chief Security Officer (CSO).

Within enterprises, SOC teams typically provide a <strong>central</strong> capability overseeing all aspects of SIEM/SOAR systems for the entire enterprise. This is so the team can correlate events to determine if they are related to each other. The SOC team's analysis often also incorporates events occurring in society at large, such as sentiment analysis of social media.
Specifically, the SOC monitors and analyzes security breaches such as <strong>malware</strong> and <strong>phishing</strong> attacks to adjust security controls and policies.

A "platform team" of DevSecOps technicians is usually specialized in setting up the hardware and software of an SIEM/SOAR system and keeping it current and secure.
They also set up the collection of data security data from network devices, servers, domain controllers, and more. The platform team works with other teams to ensure that the SIEM/SOAR system is configured to emit data into the central SIEM and security scanning in each system's CI/CD workflow. 

SOC Analysts prioritize and investigate security incidents. They maintain a 24/7/365 (continuous) view of the organization’s security posture. They identify and triage possible threats based on signatures and rules based on known threat signatures: Indicators of Attack (IOA) resulting in <a target="_blank" href="https://www.darkreading.com/cyberattacks-data-breaches/top-15-indicators-of-compromise">Indicators of Compromise (IoC)</a>.

Like FEMA, senior SOC professionals lead the lifecycle of <strong>incident management</strong> and recovery efforts within other departments. They escalate incidents to management to report incidents internally and publicly.

## Next Gen

SIEM solutions aim to improve KPIs <strong>Mean Time To Detect (MTTD)</strong> and <strong>Mean Time To Respond (MTTR)</strong> for IT security teams by reducing time wasted on <strong>false-positives</strong>.

   * Real-time visualizations to <strong>prioritize</strong> focus on the most important, high-risk activities. This includes the ability to measure status against regulatory frameworks such as PCI DSS) for risk prioritization and management 

   * Open, ‘big data architecture’ allows quicker integration with enterprise infrastructure including cloud, on-site and BYOD (in a scaleable way)

   * Detect <strong>insider threats</strong>
   
   * Automatically generate reports to meet data compliance standards including PCI DSS, GDPR, HIPAA, SOX.

   * integration of threat intelligence from custom, open-source and commercial sources, interacting with other security technologies to automatically carry out the initial steps of incident response.

   * "<a target="_blank" href="https://www.fireeye.com/products/helix/user-behavior-analytics.html">User Entity Behavior Analytics (UEBA)</a>" (using Machine Learning) highlights significant changes in behavior to better understand event context and recognize intent within specific scenarios. It models the behavior of both humans and also the machines within network, offering advanced threat detection.

* Integration with Intrusion Detection Systems (IDS) and Intrusion Prevention Systems (IPS) (such as SecurityOnion) to provide real-time analysis of security alerts generated by applications and network hardware.
