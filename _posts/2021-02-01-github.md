## package.json in root

There are two competing utilities to automate install of dependencies specified in <tt>import</tt> statements within NodeJs code:: npm and yarn.

   * yarn users create a <tt>yarn.json</tt> file.

   * npm users create a <tt>package.json</tt> file

Here is a sample <tt>package.json</tt> file:

* <strong>"dependencies"</strong> are packages required by the app in production.

* <strong>"devDependencies"</strong> are packages that are only needed for local development and testing.

* <strong>"resolutions"</strong> specifies <a target="_blank" href="https://classic.yarnpkg.com/lang/en/docs/selective-version-resolutions/">custom package versions</a> or ranges instead of waiting for the author of transitive sub-dependencies to update their package dependencies (to resolve a GitHub Dependabot alert). Or your dependency defines a broad version range and your sub-dependency has a problematic update so you want to pin it to an earlier version. 

   <pre>  "resolutions": {
    "@typescript-eslint/eslint-plugin": "^4.6.1",
    "@typescript-eslint/parser": "^4.6.1",
    "jest": "26.6.0"
   </pre>

So <tt>"jest": "26.6.0"</tt> serves to specify a version without the security vulnerability which should be used inside transitive dependencies.

If you use yarn, the above is instead of <a target="_blank" href="https://github.com/yarnpkg/rfcs/blob/master/implemented/0000-selective-versions-resolutions.md">manual edits in the yarn.lock file</a> before running <tt>yarn install</tt>.

### Scripts in npm package.json

References:
   * https://medium.com/learnwithrahul/understanding-npm-dependency-resolution-84a24180901b
   * https://www.digitalocean.com/community/tutorials/how-to-use-node-js-modules-with-npm-and-package-json
   <br /><br />

<a target="_blank" href="https://stackoverflow.com/questions/52416312/npm-equivalent-of-yarn-resolutions">However</a>, npm has a if you use npm rather than yarn, you can change the <tt>package-lock.json</tt> file and running npm, use <a target="_blank" href="https://docs.npmjs.com/cli/v8/configuring-npm/package-json#overrides">overrides</a> use <a target="_blank" href="https://github.com/rogeriochaves/npm-force-resolutions">github.com/rogeriochaves/npm-force-resolutions</a> which forces the installation of specific version of a transitive dependency, as a last resort after contacting maintainers of top-level dependency libraries.

1. The utility uses Clojure, so <a target="_blank" href="https://clojure.org/guides/getting_started">install it</a>

   <pre>brew upgrade clojure/tools/clojure</pre>

1. Add to package-json

   <pre>  {,
     "scripts": {
    "preinstall": "npx npm-force-resolutions"
    </pre>

1. Run npm install as you would normally do:

   <pre>npm install</pre>

1. Confirm that the right version was installed:

   <pre>npm ls hoek</pre>


## ESLint install

1. In package.json, <tt>npx eslint</tt> temporarily installs and runs eslint (on every run).
   <pre>  "resolutions": {
    "@typescript-eslint/eslint-plugin": "^4.6.1",
    "@typescript-eslint/parser": "^4.6.1",
    </pre>

1. In .vscode/settings.json

   This invokes ESLint on each save:

   <pre>{
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": true
  }
}
   </pre>

   ESLint catches "code smells" according to a set of rules hopefully agreed upon by the team, which is why it's in the team's GitHub instead of locally on your laptop.

1. In file <strong>.eslintignore</strong>

   <pre>dist
cdk.out
node_modules
build
   </pre>

1. In file <strong>.eslintrc</strong>

   <pre>{
  "root": true,
  "parser": "@babel/eslint-parser",
  "parserOptions": {
    "requireConfigFile": false
  }
}
   </pre>
