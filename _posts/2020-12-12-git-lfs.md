Those who store binary files in the same repo as their text would experience much faster push and pull times if they instead use gif-lfs.

Git-LFS (Large File System) is actually a misnomer for a way to store and retrieve <strong>binary files</strong>
from GitHub in a system designed to store <strong>text</strong> files.

{% include whatever.html %}

Examples of binary files are: pdf files, videos (mp4), audio samples (.mp3), graphics (.png, .jpg, etc.). 
Other examples are text pointers, datasets, etc.
Java .war files and .NET Intermediate Language (IL) files can also be considered binary files.

Major SaaS SCM vendors offer their own <strong>LFS store</strong> service to store binary files:

   * GitHub: https://github.blog/2015-04-08-announcing-git-large-file-storage-lfs/
   * GitLab: https://docs.gitlab.com/ee/topics/git/lfs/
   * BitBucket: 
   <br /><br />

There is a DIY Git-LFS server that stores files on AWS S3 at https://github.com/meltingice/git-lfs-s3 

(Gogs, a Git service that runs on your own hardware, does not have built-in Git-LFS support.)

TUTORIAL: <a target="_blank" href="https://www.atlassian.com/git/tutorials/git-lfs">https://www.atlassian.com/git/tutorials/git-lfs</a>is a great introduction, with cartoons.

But most SVM users don't know or care about LFS because they have not created individual files larger than the <strong>2 GB</strong>that GitHub can handle. 
CAUTION: Video files can easily exceed that size.

Also, due to their size, binary files should really be stored at a SaaS service (such as Clooudinary) where they can be <strong>automatically resized</strong> for various client form factors and then duplicated in a set of servers for fast retrieval world-wide.

So an alternative to Git-LFS is <a href="#DVC">DVC</a>. Unlike git-lfs, DVC doesn't require installing a dedicated server; It can be used on-premises (NAS, SSH, for example) or with any major cloud provider (S3, Google Cloud, Azure).

<a name="Installation"></a>

## Installation

1. Install git

2. Download and install the Git command line extension (written in Go) from <a target="_blank" href="https://github.com/git-lfs/git-lfs">https://github.com/git-lfs/git-lfs</a>

   Within MacOS, Homebrew: 

   <pre><strong>brew install git-lfs</strong></pre>

   Alternately, to use MacPorts: 

   <pre><strong>port install git-lfs</strong></pre>

   Within Windows:

   <pre><strong>choco install git-lfs -y</strong></pre>

   Within Ubuntu:

   <pre><strong>sudo apt install git-lfs</strong></pre>


   <a name="ConfigGlobal"></a>

   ## Configure globally

   <a target="_blank" href="https://www.youtube.com/watch?v=006RUPVIP-c&t=14m45s">VIDEO</a>:
   <a target="_blank" href="https://www.youtube.com/watch?v=uLR1RNqJ1Mw">
   Git Large File Storage - How to Work with Big Files</a> Jun 12, 2015 by "GitHub Training & Guides"

1. Set up Git LFS for your user account by running (only once):

   <pre><strong>git lfs install</strong></pre>

   The command edits file <tt>~/.gitconfig</tt> to add activation of Git's internal clean and smudge filters:

   <pre>[filter "lfs"]
    clean = git-lfs clean %f
    smudge = git-lfs smudge %f
    required = true
   </pre>

   The clean filter is invoked 

   The smudge filter is invoked upon git checkout to find LFS objects within <tt>.git/lfs/objects</tt> or the hosted LFS store (in the back-end).


   ## In each repo

   The command above changes the content of git's <tt>.config</tt> file and <strong>Git Hooks</strong> within the <tt>.hooks</tt> folder within the <tt>.git</tt> folder initialized by Git within <strong>each repository</strong> Git manages. Listed here by sequence of execution:

   1. pre-push
   2. post-checkout
   3. post-commit
   4. post-merge 
   <br /><br />

   Git message

   git-LFS works by adding commands within <strong>Git Hooks</strong> on <strong>every user's laptop</strong>:


   These hooks replace files with pointers to a different registry, such as GitHub LFS or JFrog Artifactory.


1. Specify all <strong>file extension media types</strong> to be tracked (managed) by Git-LFS:

   <pre><strong>git lfs track "images/"  # all files in folder
git lfs track "*.zip"
git lfs track "*.tar"
git lfs track "*.fbx"
git lfs track "*.stl"   # 3D models
git lfs track "*.pdf"
git lfs track "*.psd"   # Adobe project
git lfs track "*.png"
git lfs track "*.jpg"
git lfs track "*.gif"   # animations
git lfs track "*.mp4"   # videos
git lfs track "*.mp3"   # audios
git lfs track "*.aiff"
   </strong></pre>

   The command can be run anytime to configure more file extensions.

   PROTIP: Each of the above commands adds in file <tt>.gitattributes</tt> a line such as:

   <pre>*.png filter=lfs diff=lfs merge=lfs -text</pre>

   <pre>test_LFS.bak filter=lfs diff=lfs merge=lfs -text</pre>

1. Avoid issues with line endings when switching between Windows and Mac with this entry in <tt>.gitattributes</tt>:

   <pre>* text=auto</pre>

   * https://www.git-scm.com/docs/gitattributes
   * https://dev.to/deadlybyte/please-add-gitattributes-to-your-git-repository-1jld
   * https://docs.github.com/en/get-started/getting-started-with-git/configuring-git-to-handle-line-endings
   <br /><br />

1. List what files LFS is managing:

   <pre><strong>git lfs ls-files
   </strong></pre>

1. Make sure .gitattributes is tracked:

   <pre><strong>git add .gitattributes
git commit -m "Add attributes for LFS"
git push origin master
   </strong></pre>

    Note that defining the file types Git LFS should track will not, by itself, convert any pre-existing files to Git LFS, such as files on other branches or in your prior commit history. 


   ## Add binary file

   <pre><strong>git add huge/* </strong></pre>

   PROTIP: The above command results in binary file types specified being moved within the <strong>lfs</strong> folder within the repo's <strong>.git</strong> folder.

   Upon git push, notice:

   <pre>Uploading LFS objects:</pre>

   After the upload, on Github.com, a "LFS" marker is shown next to each binary file managed under LFS.

   Notice that large (binary) files remain within the repo locally.


   ## Migrate

1. command, which has a range of options designed to suit various potential use cases.

   <pre><strong>git lfs migrate</strong></pre>

   The above command creates files that contain a pointer to where the actual file contents are stored:

   <pre>version https://git-lfs.github.com/spec/v1
old sha256:f23b93923ac92811771c3929d2323eeab233aa93239b32323b1ac222
size 1122323
   </pre>

   ## Commit LFS

1. Commit and push to GitHub as per normal:

   <pre><strong>git add file.psd
git commit -m "Add design file"
git push origin master
   </strong></pre>


   ## Clone/merge of lfs

   When a repo using LFS is cloned on another folder/laptop, the "git-merge" hook downloads binary fines to the <tt>.git/lfs</tt> folder within the repo.

   REMEMBER: GitHub does not (cannot) identify what has changed within each file like it does within text files.

1. To manually change the size of a file:

   <pre><strong>fallocate -l 1000001 binary/some-1mb.mp4</strong></pre>

   REMEMBER: Because intermediate versions of binary files are not tracked like git-managed versioned text files,
   only the most recent binary file is retrieved from LFS.


## Un-installation

   <pre><strong>git lfs uninstall</strong></pre>

## Other

To configure git-lfs (GitHub’s Large File System), commands like these are placed in hook files:

   <pre><strong>#!/bin/sh
command -v git-lfs >/dev/null 2>&1 || { echo >&2 "\nThis repository is configured for Git LFS but 'git-lfs' was not found on your path. If you no longer wish to use Git LFS, remove this hook by deleting .git/hooks/post-commit.\n"; exit 2; }
git lfs post-commit "$@"
   </strong></pre>

   The above commands first checks if git-lfs is installed, then performs the git lfs command, with “$@” forwarding the attributes passed into the hook file.

## DVC (Data Version Control)

<strong>dvc</strong> is a CLI package that wraps around (extends) Git and git-lfs to store large files in away from GitHub.

dvc also enable git checkout of versioned data.

1. DVC's <a target="_blank" href="https://dvc.org/doc/get-started/install">installers</a> include snap, pip, brew, choco, conda (Anaconda) or an OS-specific package. It installs/upgrades python3, grpc, awscli, azure-cli, sqlite, Qt, opencv, imagemagick, ansible, vtk, apache-arrow, thrift, zstd, and other packages it needs.

   <a target="_blank" href="https://dvc.org/">https://dvc.org</a> is Apache2 open sourced at <a target="_blank" href="https://github.com/iterative/dvc">https://github.com/iterative/dvc</a>

   On MacOS:

   <pre><strong>brew install dvc</strong></pre>

1. Make a folder and cd into it.
1. <tt>dvc init</tt> establishes metric collection and creates folder <strong>~/.dvc</strong>.

   <a name="dvc_add"></a>

1. <tt>dvc add data/data.xml</tt>

   This creates a .dvc file which contains a MD5 hash value of the contents. This "pointer" enables versioning of the data.

1. <tt>cat data/data.xml.dvc</tt>

   <pre>outs:
- md5: a23023923ab033023f09a9bbc333d
  path: data.xml</pre>

   In other words, DVC uses reflinks (or hardlinks) to avoid copy operations on checkouts.

1. <tt>git add data/data.xml.dvc</tt>

1. In the imported .gitignore file there is a line to not upload file "/data.xml". Add it:

   <tt>git add data/.gitignore</tt>

   PROTIP: This is so that when the actual (big) file is pulled in locally, it won't be accidentally uploaded into GitHub.

1. <tt>git commit -m "Add raw data"</tt>
1. <tt>cd data</tt>

1. On Google Drive, get the URL to a folder:

   <tt>dvc remote add -d storage gdrive://234203409023909fabcde</tt>

<a name="Github-LFS-Store"></a>

## Github.com LFS Store

GitHub provides 1GB of free LFS storage.
Previous to December 2020, GitHub had users pre-pay for storage each month ($60 for each 50GB block).
However, GitHub now has a pay-as-you-go invoicing for LFS storage and bandwidth usage.

The Admin can disable LFS at the Organizational level after removing existing LFS objects. 
A support ticket needs to be raised with object IDs of specific LFS files to be deleted. 
Find each object ID using this command (replacing "path/to/file" with the path to the file in your repository):

   shasum -a 256 path/to/file
