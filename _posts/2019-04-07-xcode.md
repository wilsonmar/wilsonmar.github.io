<a target="_blank" href="https://wilsonmar.github.io/Xcode">This tutorial</a> describes the installation and usage of <tt>gcc</tt>, <tt>make</tt> and other executable utilities from Apple which 
Homebrew, Python, and many other development tools need.

<a name="2installers"></a>

## Overlapping installers!

The executables from Apple are installed two separate ways. Imagine a Venn diagram of overlapping circles:

   * <strong>CommandLineTools</strong> at <tt>/Library/Developer/CommandLineTools</tt>

   * <strong>Xcode IDE</strong> at <tt>~/Applications/Xcode.app</tt>

Each has a separate install procedure.

Xcode is Apple's free IDE developers use to create custom programs for all Apple devices (macOS, iPhone, iPad, Apple Watch). Increasingly, Machine Learning developers are using the Swift language.

Because XCode.app is very large (several Gigabytes), developers who do not create Apple programs can save disk space by not installing it. Instead, they install just the CommandLineTools needed by Homebrew and others.


<a name="XCode.app"></a>

## About Xcode.app

Since the Apple Store only handles individual .app files, other mechanisms are needed to install additional programs needed as a pre-requisite by Homebrew, Python, and other development programs.

BTW Xcode only works on macOS. There is no Windows PC version.

PROTIP: Skip Apple's websites and App. <a href="#2installers">Click here for install instructions (below)</a>.

Otherwise, read on for a run-around.

0. Use an internet browser to view Apple's Xcode marketing page at:

   <a target="_blank" href="https://developer.apple.com/Xcode/">
   https://developer.apple.com/Xcode</a>

   Xcode "includes everything you need to create amazing apps for all Apple platforms. Now Xcode and Instruments look great in the new Dark Mode on macOS Mojave. The source code editor lets you transform or refactor code more easily, see source control changes alongside the related line, and quickly get details on upstream code differences. You can build your own instrument with custom visualization and data analysis. Swift compiles software more quickly, helps you deliver faster apps, and generates even smaller binaries. Test suites complete many times faster, working with a team is simpler and more secure, and much more.".
   
   BTW the "Apple platforms" include MacOS, iPhone, iPad, Apple TV, and Apple Watch.

Xcode does not come with macOS because of <a href="#XcodeSize">its large size</a> 
and because many users of macOS don't need it to do software development.

Developers who use another IDE (such as Visual Studio, Eclipse, etc.) would only need to install Xcode's <strong>command line utilities</strong> for the <strong>GCC compiler</strong> Python needs to build code.

PROTIP: Newer versions of Xcode installer also installs a Git client.

## cc and gcc needed

Homebrew, Python, and many other development tools need the <tt>cc</tt>, <tt>gcc</tt>, <tt>make</tt> and other executable utilities from Apple.

1. Verify the version of GCC installed:

   <pre><strong>gcc --version</strong></pre>

   If Xcode.app was installed, you would see (at time of writing):

   <pre>Configured with: --prefix=/Library/Developer/CommandLineTools/usr --with-gxx-include-dir=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include/c++/4.2.1
Apple clang version 13.0.0 (clang-1300.0.29.3)
Target: x86_64-apple-darwin21.1.0
Thread model: posix
InstalledDir: /Library/Developer/CommandLineTools/usr/bin
   </pre>

   Previously, it was instead:

   <pre>Apple LLVM version 10.0.1 (clang-1001.0.46.4)
InstalledDir: /Applications/Xcode.app/Contents/Developer/Toolchains/XcodeDefault.xctoolchain/usr/bin
   </pre>

   If CommandLineTools is installed, you would see (at time of writing):

   <pre>Configured with: --prefix=/Library/Developer/CommandLineTools/usr --with-gxx-include-dir=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include/c++/4.2.1
Apple clang version 11.0.3 (clang-1103.0.32.62)
Target: x86_64-apple-darwin19.4.0
Thread model: posix
InstalledDir: /Library/Developer/CommandLineTools/usr/bin
   </pre>

   If "Command not found" appears, either <a href="#InstallCU">install CommandLineTools</a> or install XCode.app, then return <a name="gcc">here</a>.

   
   ### xcrun for path

1. Identify the <strong>path of the gcc</strong>

   <pre><strong>xcrun --find gcc</strong></pre>

   If Command Line Utilities is installed, the response is:

   <pre>/Library/Developer/CommandLineTools/usr/bin/gcc</pre>

   If Xcode.app is installed, the response is:

   <pre>/Applications/Xcode.app/Contents/Developer/usr/bin/gcc</pre>

   If neither is installed:
    
   <pre>xcrun: error: active developer path ("/Library/Developer/CommandLineTools") does not exist
Use `sudo Xcode-select --switch path/to/Xcode.app` to specify the Xcode that you wish to use for command line developer tools, or use `Xcode-select --install` to install the standalone command line developer tools.
See `man Xcode-select` for more details.
   </pre>

   The same for <tt>make</tt>.

   Again, if "Command not found" appears, either <a href="#InstallCU">install CommandLineTools</a> or install XCode.app, then return here.

   
   ## Files and Folders

   Let's see what is in those folders:

1. If CommandLineTools was installed:

   <pre><strong>ls -al /Library/Developer/CommandLineTools
   </strong></pre>

   The response would be:

   <pre>Library      SDKs    usr</pre>

1. If Xcode.app was installed:

   <pre><strong>ls -al /Applications/Xcode.app/Contents/Developer/
   </strong></pre>

   The response would have more than what's in CommandLineTools:

   <pre>Applications Library      Makefiles    Platforms    Toolchains   Tools        usr</pre>



   <a name="Xcodebuild"></a>

   ### Xcode.app Version

1. From within a Terminal, type:

   <pre><strong>/usr/bin/Xcodebuild -version
   </strong></pre>

   If Command Line Tools was installed, you would see:
   
   <pre>Xcode-select: error: tool 'Xcodebuild' requires Xcode, but active developer directory '/Library/Developer/CommandLineTools' is a command line tools instance</pre>

   If Xcode is installed, you would get a version code that should match up with the Build Number on the Apple web page:

   <pre>Xcode 10.2.1
Build version 10E1001
   </pre>

1. For a more precise version number and other info (macOS Mavericks version and up):

   <pre><strong>pkgutil --pkg-info=com.apple.pkg.CLTools_Executables
   </strong></pre>

   A sample response, at time of writing:

   <pre>package-id: com.apple.pkg.CLTools_Executables
version: 13.1.0.0.1.1633545042
volume: /
location: /
install-time: 1637303193
groups: com.apple.FindSystemFiles.pkg-group
   </pre>

   The previous command was constructed based on a search of tools package names:

   <pre>pkgutil --pkgs | grep -i tools
   </pre>

   The response:

   <pre>com.apple.pkg.CLTools_Executables
com.apple.pkg.CLTools_SDK_macOS1015
com.apple.pkg.CLTools_SDK_macOS1014
com.apple.pkg.CLTools_macOS_SDK
...
   </pre>


   ## xcode-select

   Unlike other programs, a <tt>xcode-select</tt> command is needed to designate where to find gcc and other Apple Developer utilities.

1. In a Terminal window, find out what has been installed: 

   <pre><strong>xcode-select -p
   </strong></pre>

   <tt>-p</tt> is the same as <tt>--print-path</tt>

   If XCode CLI was installed, you should see:

   If the Xcode-select command is not found, choose to <strong>either</strong> <a href="#InstallCU">install Command Line Tools</a> or install the full Xcode IDE.

   <pre>/Library/Developer/CommandLineTools</pre>

   If XCode.app was installed, you should instead see:

   <pre>/Applications/Xcode.app/Contents/Developer</pre>



   ## Specifying the XCode utility used

   PROTIP: Xcode.app cannot be installed if Command Utilities has already been installed. So the installation program needs to first check whether XCode.app or CommandLineTools is installed.

   Choose which one you want used:

1. To specify use of the Xcode.app (IDE):

   <pre><strong>sudo xcode-select --switch /Applications/Xcode.app
   </strong></pre>

1. To specify use of CommandLineTools:

   <pre><strong>sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
   </strong></pre>
   

1. Reset

   <pre><strong>sudo xcode-select -r</strong></pre>

## Install Command Line Utilities only

   See https://developer.apple.com/library/archive/technotes/tn2339/_index.html and <a target="_blank" href="http://osxdaily.com/2014/02/12/install-command-line-tools-mac-os-x/">http://osxdaily.com/2014/02/12/install-command-line-tools-mac-os-x</a>

1. To install Command Line Utilities:

   <pre><strong>xcode-select --install</strong></pre>

   Alternately, <a target="_blank" href="https://gist.github.com/brysgo/9007731">this script</a>:

   <pre>xcode-select --install > /dev/null 2>&1
if [ 0 == $? ]; then
    sleep 1
    osascript <<EOD
tell application "System Events"
    tell process "Install Command Line Developer Tools"
        keystroke return
        click button "Agree" of window "License Agreement"
    end tell
end tell
EOD
else
    echo "Command Line Developer Tools are already installed!"
fi
   </pre>




   <a target="_blank" href="https://github.com/timsutton/osx-vm-templates/blob/ce8df8a7468faa7c5312444ece1b977c1b2f77a4/scripts/xcode-cli-tools.sh">A shell script</a> uses these commands to not require manual clicking on the dialog that pops up (below):

   <pre><strong>#!/bin/sh
# Create placeholder file checked by CLI updates' .dist code in Apple's SUS catalog:
touch /tmp/.com.apple.dt.CommandLineTools.installondemand.in-progress;
# Find the CLI Tools update:
PROD=$(softwareupdate -l |
  grep "\*.*Command Line" |
  head -n 1 | awk -F"*" '{print $2}' |
  sed -e 's/^ *//' |
  tr -d '\n')
# Unless "No new software available.", install it:
softwareupdate -i "$PROD" -v;
   </strong></pre>

   ![Xcode-select-prompt-444x148](https://user-images.githubusercontent.com/300046/83383584-acf52d80-a3a2-11ea-9316-6ac91ccb99a4.jpg)

1. If you see this pop up, manually click "Install", "Agree", then "Install" to the "Updates Available" pop-up.

1. CAUTION: The large number of files means it can a long time. It took 13 minutes on my 10mbps line.

1. When you see "The software was installed.", click "Done" to dismiss the pop-up.

1. If you have the <tt>tree</tt> utility installed:
   
   <pre><strong>tree /Library/Developer/CommandLineTools | tail -1</strong></pre>

   Would yield (at time of writing):

   <pre>16143 directories, 72910 files</pre>


<a name="UnInstallCU"></a>

## UnInstall Command Line Tools

   PROTIP: This is also how you <strong>upgrade Command Line Tools</strong>.

1. Go to the parent folder where Command Line Tools is installed:

   <pre><strong>cd /Library/Developer 
   </strong></pre>

1. Get a list of its folders:

   <pre><strong>ls CommandLineTools
   </strong></pre>

   If Command Line Tools were installed, the response would be :
   
   <pre>Library	SDKs	usr</pre>

1. Remove all files in that folder, provide a password for elevated permissions to get all the files:

   <pre><strong>sudo rm -rf /Library/Developer/CommandLineTools
   </strong></pre>

   The response is a lot of files removed (to the Trash).

   Now <a href="#InstallCU">install CommandLineTools</a> (or <a href="#InstallIDE">install the full Xcode IDE</a>).


   CAUTION: On a Mac M1 (Apple Silicon chip, macOS 12.0 Monterey), after installed the Command Line Tools then uninstalled them by deleting /Library/Developer/CommandLineTools and running sudo xcode-select -r, I was still getting updates to the tools in System Preferences > Software Update.

   The files below are protected by SIP: to delete them, I had to disable SIP first (ie disable SIP, delete the files, re-enable SIP).

   Indeed, the receipts are at /Library/Apple/System/Library/Receipts, in the form of files

   * com.apple.pkg.CLTools_Executables.{bom,plist}
   * com.apple.pkg.CLTools_SDK_macOS*.{bom,plist}
   * com.apple.pkg.CLTools_macOS_SDK.{bom,plist}

## Xcode IDE install from Terminal

1. Make sure you have at least <strong>13GB free</strong> on your hard-drive before attempting installation.

   1. Click the Apple icon to select "About this Mac".
   2. Click "Storage" tab.
   <br /><br />

1. In an internet browser, get to the "Mac App Store Preview" for Xcode at<br /><a target="_blank" href="https://apps.apple.com/us/app/Xcode/id497799835?mt=12">https://apps.apple.com/us/app/Xcode/id497799835?mt=12</a>

   <img width="683" alt="Xcode-web-preview.png" src="https://user-images.githubusercontent.com/300046/95787611-1e20e780-0c97-11eb-97b7-a4a6a70619be.png">

1. Click <strong>View in Mac App Store</strong>, then "Open App Store.app" in the pop-up.

1. Provide your Apple ID and password. Get one if you don't already have one.

   PROTIP: DO NOT install a beta version of Xcode.

   The blue "OPEN" icon appears at the upper-right when the app is installed.
   But don't click it because we are done.

1. In Finder, look for <strong>Xcode.app</strong> in the <tt>/Applications</tt> folder.

   Alternately, on the Touchpad pinch 4 fingers together to click the <strong>App Store</strong>. 
   Type enough of "Xcode" to filter out others. 

1. To view the version, cursor to the top of the screen and click the program name next to the Apple icon to select "About Xcode":

   ![Xcode about 271x48](https://cloud.githubusercontent.com/assets/300046/21987451/dc44154a-dbc0-11e6-90b6-4dce91b8c5d2.png)



### A) Initial install from Terminal CLI

1. Open a Terminal.app console window at any directory to install -all the latest Xcode from Apple:

   <pre><strong>softwareupdate --install -a
   </strong></pre>

   The response on Catalina version of macOS:

   <pre>Software Update Tool
&nbsp;
Finding available software
&nbsp;
Downloaded macOS Catalina 10.15.5 Update
Installing macOS Catalina 10.15.5 Update
Done.
To install these updates, your computer must shut down. Your computer will automatically start up to finish installation.
Installation will not complete successfully if you choose to restart your computer instead of shutting down.
Please call halt(8) or select Shut Down from the Apple menu. To automate the shutdown process with softwareupdate(8), use --restart.
   </pre>

1. Click the Apple icon at the upper-right corner and select "Shut Down...".


   ### After starting again

2. Set Apple's licensing agreement bit:

   <pre><strong>sudo xcodebuild -license
   </strong></pre>

3. Manually agree to the terms.

4. Get the version number of the new version.

### Xcode IDE Upgrade

Over time, Apple updates Xcode and its command line utilities.

1. Click the Apple icon, then click <strong>System Preferences</strong>. Here is an example notification:

   ![Xcode-cli-update-436x98-4795](https://user-images.githubusercontent.com/300046/56460275-7e162680-635d-11e9-8d3c-0bb89457dcd8.jpg)

2. Search for "Software Updates" or click the icon.
2. Click "Update Now" if that appears. (but first do a backup.)
3. Click "Agree" to the EULA.
4. When done, view the <a href="#versions">version numbers installed</a>.

## Xcode FileMerge tool

Xcode graphically compares files and directories.

1. Open Xcode. This takes a few seconds.

1. Right-click on Xcode icon. Select "Open Developer Tool". Select "FileMerge".

1. Specify one file to compare.

1. Specify the other file to compare.

1. Click "Compare".
