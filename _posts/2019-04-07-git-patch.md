<a target="_blank" href="https://wilsonmar.github.io/">This</a> is a hands-on tutorial on how to use Git patch from the command line and in a Bash script.

## Man page

0. On a Terminal, to see Git's documentation on the git patch command:
   <pre><strong>
   man git-patch
   </strong></pre>

   A Git patch file is a <strong>mail document</strong> which updates a Git repository using the <strong>git am</strong> command instead of a <tt>git commit</tt> command.

   This approach is used by Linux Core developers.

   PROTIP: This can be a scary operation, so I've written a <strong>Bash script</strong> to make it easier, faster, and safer.

1. In an internet browser such as Google Chrome or Mozilla Firefox, visit my Bash script "git-patch.sh" at:

   <a target="_blank" href="https://github.com/wilsonmar/git-utilities/blob/master/git-patch.sh">https://github.com/wilsonmar/git-utilities/blob/master/git-patch.sh</a>

   The Bash scripting in the file is explained in:<br />
   <a target="_blank" href="https://wilsonmar.github.io/bash-coding/">https://wilsonmar.github.io/bash-coding</a> and in this document.

   The script "git-patch.sh" clones a repo, creates a patch, opens another repo, and applies those changes.

   
   
   NOTE: Thanks to <a target="_blank" href="https://www.linkedin.com/in/sikachu/">Prem Sichanugrist</a> for his <a target="_blank" href="https://thoughtbot.com/blog/send-a-patch-to-someone-using-git-format-patch">blog about git patch</a> of piping several messages into a single patch file.


## Git Branching Model

Git patches are used by the Git core team branching model is described in <a target="_blank" href="https://www.youtube.com/watch?v=diYgS3So6Yo&t=5m3s">this Oct 21, 2016 video</a> by <a target="_blank" href="https://www.linkedin.com/in/durdn/">Nicola Paolucci</a> when he was a Developer Advocate at Atlassian.

![git-patch-flow-1082x487-21333](https://user-images.githubusercontent.com/300046/55745009-8a13f700-59f3-11e9-8a35-55109c2143af.jpg)

   * np/topic branch are discussed using patches emailed
   * pu = proposed updates
   * next branch are changes about to be merged into master
   * next and maintenance branches are reset after releases
