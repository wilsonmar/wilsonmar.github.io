<a target="_blank" href="https://continuousdelivery.com/">Continuous Delivery (CD)</a> takes code through a pipeline to production as low-risk, predictable, routine affairs performed on demand. This is achieved by eliminating delays during "code freezes" for integration, testing, and hardening phases that traditionally followed “dev complete”. GoCD achieves CD with an <strong>automated pipeline of continuous testing and acceptance</strong> of small increments of changes to code always in a deployable state (even by teams of thousands of developers making changes on a daily basis).

## Advantages over competitors

GoCD's provides visibility (traceability) over the end-to-end workflow from version control to production.

GoCD's <strong>Value Stream Map</strong> tracks each change from commit to deploy. This is so when things go wrong, it's easy to identify both the upstream cause and the downstream effects.

## Internal architecture

GoCD's proposition is similar to GitLab - providing the most <strong>common CD scenarios out of the box</strong> - while Jenkins aims for general-purpose automation by extensibility with 3rd party plugins. GoCD avoids the issue of plugins that can be  missing features, obsolete, or does not work well with others.

* Pipelines
   * Sequential Stages with Jobs running in parallel
      * Tasks (commands invoking shell scripts)
   * Environments
      * Agents
         * Resources (tags about capabilities of each agent)

GoCD has a handful of extension points that are interoperable: 

* SCM (Source Control Management)
* tasks 
* notifications, 
* authentication and authorization, 
* configuration, 
* elastic agents (for parallel execution at scale)
