Templating Terraform for "point and click".

Instead of users submiting to a manual ticketing queue (which breaks agility),
system auto-approves if role-based policies does not identify issues.

To apply policies, TFE adds a <strong>sentinel</strong> command between terraform plan and apply commands.
Sentinel applies policies as code.

<a target="_blank" href="https://www.youtube.com/watch?v=qfQrsaFnsmU" title="9:17 Oct 4, 2019">
VIDEO: Terraform Enterprise: Understanding Workspaces and Modules</a>
by Teddy

A Workspace consists of:

* A Terraform configuration
* Values for variables used by the configuration
* Presistent stored state for the resources managed by the config
* Historical state and run logs
<br /><br />

NOTE: There is a 1:1 match between state and config.

A Workspace for each team which manage certain resources (configs),
with different RBAC permissions for each team/workspace:

There is one set of each for each environment:
   * Dev
   * QA
   * Stage (green)
   * Prod (blue)

Create a <strong>module registry</strong> containing reusable module so consumers don't need to know how the module works. Consumers would only need to supply DNS name.
