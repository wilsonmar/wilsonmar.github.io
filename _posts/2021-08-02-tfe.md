## Why PaC (Policy as Code)

When each change in policy code triggers automated checks for compliance in CI/CD pipelines, it's like having a Security Engineer always review every change, which is too costly to achieve manually.

> Policy-as-code is crucial to scaling security governance across a large number of development teams.

Each review generates an <strong>attestation</strong> (evidence) to show auditors compliance (that security policies are continually enforced).

When security policies are not just in a Word document but defined and automated like source code and versioned in GitHub, TFE treats <strong>Policy as Code</strong> (PaC).

> To "shift-left" checking earlier in the development lifecycle, verify locally on laptops before resources are deployed in the public cloud.

### Enforcement levels

Before we dive into Sentinel HCL files, know that each policy is defined with an Enforcement Level which defines the <strong>importance</strong> of that policy and thus what happens when a violation of that policy is detected:

* <strong>"hard-mandatory"</strong> violations cause the run to be halted so that it can be resolved. 

* <strong>"soft-mandatory"</strong> violations can be overriden on a case-by-case basis (ignored) by any user with the "Manage Policy Overrides" permission. QUESTION: How?

* <strong>"advisory"</strong> violations are surfaced as informational to the user, and not interrupt the run.


### Sentinel.hcl

Since January 20, 2021, a HCL (rather than JSON) format <tt>sentinel.hcl</tt> configuration file specifies <a target="_blank" href="https://github.com/hashicorp/terraform-guides/tree/master/governance/third-generation">"third-generation" *.sentinal policy language files</a>, each with an enforcement_level:

HCL (Hashicorp Configuration Language) enables addition of comments in JSON files, which by definition does not recognize comments.

My example-Sentinel.hcl file invokes the most common policies:

<pre>policy "enforce-mandatory-tags" {
    source = "./enforce-mandatory-tags.sentinel"
    enforcement_level = "hard-mandatory"
}
policy "restrict-allowed-vm-types" {
    source = "./restrict-allowed-vm-types.sentinel"
    enforcement_level = "soft-mandatory"
}
policy "restrict-app-service-to-https" {
    source = "./restrict-app-service-to-https.sentinel"
    enforcement_level = "advisory"
}
policy "read-only-friday" {
    # Don't risk ruining someone's weekend:
    source = "./read-on-friday"
    enforcement_level = "advisory"
}
policy "aws-cis-4.1-networking-deny-public-ssh-acl-rules" {
  # (networking outside AWS to get Raw files in GitHub):
  source            = "https://raw.githubusercontent.com/hashicorp/terraform-foundational-policies-library/master/cis/aws/networking/aws-cis-4.1-networking-deny-public-ssh-acl-rules/aws-cis-4.1-networking-deny-public-ssh-acl-rules.sentinel"
  enforcement_level = "advisory"
}
</pre>

Indentation is two or more spaces.

<tt>./this.sentinel</tt> specifies the current folder.

<tt>../this.sentinel</tt> specifies the parent folder of the current file.

<tt>../../this.sentinel</tt> specifies a folder two levels up from the current file.

Use of the above folder reference requires a standard.

https://github.com/hashicorp/terraform-foundational-policies-library/tree/master/cis/aws/networking/aws-cis-4.1-networking-deny-public-ssh-acl-rules/test/aws-cis-4.1-networking-deny-public-ssh-acl-rules






## Policy languages

The language to define policies needs to be a <strong>programming language</strong> with if/then/else using variables, loops referencing arrays, functions, etc.

<a target="_blank" href="https://medium.com/@mathurvarun98/how-to-write-great-rego-policies-dc6117679c9f">NOTE</a>: OPA makes use of its yaml-format <a target="_blank" href="https://www.openpolicyagent.org/docs/latest/policy-language/">"Rego language"</a> for defining policy rules. Rego extends the <a target="_blank" href="https://en.wikipedia.org/wiki/Datalog">Datalog query language</a>.

OPA was created by <a target="_blank" href="https://academy.styra.com/courses/opa-rego">Styra.com</a>, which provides support and training on OPA and the <strong>Rego language</strong>. Rego has Python-esque import statements, no semicolons, print() functions, <a target="_blank" href="https://thenewstack.io/5-things-you-didnt-know-about-open-policy-agent/">list comprehensions</a>, etc.

## Mocks in Sentinel HCL

https://docs.hashicorp.com/sentinel/writing/testing#mocking
Mocks are used during testing to simulate scenarios where a policy would pass or fail.

Mocking can be done by setting various parts of the configuration file which set static globals and imports.

One way to mock is to shift parameter values to reference globals, simulating an environment where variables are already defined instead of being retrieved for reals. Example: https://docs.hashicorp.com/sentinel/writing/testing#mocking-globals

<pre>global "hour" {
  value = 14
}</pre>

Mocks can also be done by using an <strong>import</strong>.

https://github.com/hashicorp/terraform-guides/tree/master/governance/third-generation/aws/mocks

<pre>mock "time" {
  data = {
    now = {
      weekday_name = "Monday"
      hour         = 14
    }
  }
}</pre>

## TFE Server Architecture

<a target="_blank" href="https://www.terraform.io/docs/enterprise/system-overview/reliability-availability.html">This data flow diagram</a> shows TFE's internal technology choices:

![tfe-data-flow-2400x1288](https://user-images.githubusercontent.com/300046/128644885-d5c0e735-b00b-4a23-91e6-23dda96bc0bb.png)

Application Layer:

   * TFE Core - A Rails application at the center of Terraform Enterprise; consists of web frontends and background workers

   * TFE Services - A set of Go services that provide various pieces of key functionality for Terraform Enterprise

   * Terraform Workers - A fleet of isolated execution environments that perform Terraform Runs on behalf of Terraform Enterprise users

Coordination Layer:

## Ensure follow-up with ServiceNow

AWS offers the <a target="_blank" href="https://aws.amazon.com/security-hub/">AWS Security Hub service</a> which publishes security alerts from other services across regions. 

AWS Security Hub presents security alerts as a web page for users to manually review.

The cumbersome aspect here is that a central SOC team must individually analyze each alert, then notify the appropriate individuals to request remediation action. 

AWS Security Hub also sends emails of crucial and high alerts to designated individuals, but emails often are not read.

So companies that have ServiceNow make use of the <a target="_blank" href="https://aws.amazon.com/about-aws/whats-new/2020/12/aws-security-hub-now-supports-bidirectional-integration-with-service-now-itsm/">two-way automatic integration between ServiceNow and AWS Security Hub</a>

More: https://aws.amazon.com/blogs/mt/tag/servicenow/
