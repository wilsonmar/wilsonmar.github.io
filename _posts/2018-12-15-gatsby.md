This is a hands-on extended guided tour to quickly creating and publishing a feature-rich <a href="#JAMStack">JAM-stack</a> website using the Gatsby framework and CLI: locally and using Docker in AWS.

This is the narration for a video. For now it's just text.

Along the way, succinct deep-dive commentary provide insights not available anywhere else.
All on one page.

PROTIP: Rather than <a href="#FromScratch">building up from scratch</a> or <a href="#GenBasic">
generating a basic site</a>, the approach here is to <strong>automate</strong> a <strong>full-featured almost completed</strong> site which we then analyze and customize. That's usually what you encounter on the job.

<hr />

1. View <a target="_blank" href="https://www.gatsbyjs.org"><strong>https://www.gatsbyjs.org</strong></a>

   The ".org" in the URL is becuase Gatsby.js itself is a non-profit, as in free open-source, framework for creating static websites with JavaScript language, React front-end, and GraphQL protocol (the most popular frameworks).

   <a name="JAMStack"></a>

   Gatsby's architecture is a <a target="_blank" href="https://wilsonmar.github.io/jam-stack-website-project-plan/">"JAM stack"</a> -- an acronym for JavaScript, APIs, Markup (HTML). Rather than rendering HTML for every request after referencing a database, JAM sites deliver stored HTML stored after being pre-converted from Markup by developers.

   Gatsby makes use of the React front-end UI framework from Facebook.
   Thus, Gatsby can support all ever-green browsers and Internet Explorer 9+ on Windows 7+.

   Some call it a "Cloud Native Website System".

   ### Project root files and folders 

   Unlike Jekyll, Gatsby has all configuration files at the root:
   
   File <tt>README.md</tt> contains useful reference information about the project,
   adapted here:

   File <tt>gatsby-config.js</tt> is the main configuration file for a Gatsby site to specify information about your site (metadata) such as site-wide title and description, which Gatsby plugins you’d like to include, etc. (Check out the [config docs](https://www.gatsbyjs.org/docs/gatsby-config/) for more detail).

   File <tt>gatsby-browser.js</tt> specifies  usage of the [Gatsby browser APIs](https://www.gatsbyjs.org/docs/browser-apis/) (if any). These allow customization/extension of default Gatsby settings affecting the browser.

   File <tt>gatsby-node.js</tt> specifies usage of the [Gatsby Node APIs](https://www.gatsbyjs.org/docs/node-apis/) (if any). These allow customization/extension of default Gatsby settings affecting pieces of the site build process.

   File <tt>gatsby-ssr.js</tt> specifies usage of the [Gatsby server-side rendering APIs](https://www.gatsbyjs.org/docs/ssr-apis/) (if any). These allow customization of default Gatsby settings affecting server-side rendering.

   File <tt>LICENSE</tt> says Gatsby is licensed under the MIT license.

   File <tt>package-lock.json</tt> (See <tt>package.json</tt> below, first). This is an automatically generated file based on the exact versions of your npm dependencies that were installed for your project. **(You won’t change this file directly).**

   Folder <tt>fonts</tt> if the site uses custom fonts which are more stylish than the limited number of fonts that come on browsers.

   Folder <tt>node_modules</tt> is where all dependencies (npm packages) are downloaded and installed based on the manifest file<br />
   file <tt>package.json</tt> which includes metadata (the project’s name, author, etc).

   File <tt>package-lock.json</tt> defines dependencies packaged.

   File <tt>env.development</tt> contains variables such as CONTENTFUL_SPACE_ID and CONTENTFUL_ACCESS_TOKEN. These are sensitive information. So the file needs to be specified in<br />
   File <tt>.gitignore</tt> tells Git which files it should not track / not maintain a version history for.

   File <tt>.prettierrc</tt> is a configuration file for [Prettier](https://prettier.io/). Prettier is a tool to help keep the formatting of your code consistent.

   Folder <tt>src</tt> (for "source code") contains the site's content read by visitors on the "front-end" of the site (what you see in the browser) such as your site header or a page template.

1. Look into the <strong>src</strong> folder to see files and directories such as:
 
   <pre><strong>tree ./src
   </strong></pre>

   <pre>
|-- components
|   |-- header.js
|   |-- image.js
|   |-- layout.css
|   |-- layout.js
|   |-- seo.js
|-- images
|   |-- favicon.ico
|   |-- gatsby-astronaut.png
|   |-- gatsby-icon.png
'-- pages
    |-- 404.js
    |-- index.js
    |-- page-2.js
   </pre>

   PROTIP: <tt>favicon.ico</tt> is frequent a file in <tt><strong>Images</strong></tt>. Images in .png format are stored among other code here. But for production deployment, they are the basis for additional images generated in different screen sizes and formats (such as webp), and distributed for quick retrieval within various CDN end-points throughout the world.

   Writers of content spend almost all their time in the <strong>pages</strong> folder.
   
   A <tt><strong>templates</strong></tt> folder holds templating specifications.

   A <tt><strong>styles</strong></tt> folder holds CSS styling specifications.

   A <tt><strong>posts</strong></tt> folder holds markedown (.md) files containing content read by visitors.

   PROTIP: Posts are formatted by files with file extention of ".js" which are <a href="#WriteJavaScript"><strong>JavaScript</strong> program code. More on this below</a>.

   The result of <tt><strong>index.js</strong></tt> is shown when a visitor specifies just the domain name.

   The result of <tt><strong>404.js</strong></tt> is shown when a visitor specifies a path not defined.<a target="_blank" href="https://www.youtube.com/watch?v=kzWIUX3CpuI&t=4h10m45s">*</a> Advanced features include a listing of major topics (such as home, menu, contact) and presenting a search with spelling/grammar correction. The <a target="_blank" href="https://github.com/nfl/react-helmet">React Helmet plugin</a> document head manager.

   ### run develop package.json

1. Process the <tt>package.json</tt> file in development mode to a public folder:

   <pre><strong>npm run develop</strong></pre>

   This creates a folder named "public" containing compressed and minimized text files which will wait on web servers for retrieval directly by visitors. If these files are distributed in a CDN, users throughout the world (in Australia or India or Nigeria) will retrieve them very quickly.

1. List the files:

   <pre><strong>ls ./public</strong></pre>

   The folder contains:

   * index.html
   * icons folder
   * static folder
   * page-data folder
   * manifest.webmanifest
   <br /><br />

1. In a browser, view the HTML created as if you're a customer by specifying this URL:

   <pre>http://localhost:8000/</pre>

   <tt>http://</tt> is specified because no SSL/TLS certificate needs to be used on your local host server.

1. Right-click on the web page to select "View page source".

   Notice that the HTML is compressed.

1. Back on the Terminal, press control+C to cancel.

1. Create files in production mode:
 
   <pre><strong>npm run serve</strong></pre>

1. In a browser, view the HTML created as if you're a customer by specifying this URL:

   <pre>http://localhost:9000/</pre>

   ### Clean-up

1. When done, on a Terminal session, remove the work folder:

   <pre><strong>cd ~/projects
   rm -rf "$WORK_REPO"</strong></pre>

### Installing Gatsby locally

1. Install the gatsby-cli from NPM globally (for access from any folder):

   <pre><strong>npm install -g gatsby-cli</pre>

   (<tt>-g</tt> is the same as <tt>--global</tt>)

   Alternately, you may want to install a specific version that your course uses, such as:

   <pre>npm install -g gatsby-cli@2.4.5</pre>

1. Get a summary of commands:

   <pre><strong>gatsby --help</strong></pre>

1. Get the environment that Gatsby recognizes:

   <pre><strong>gatsby info</strong></pre>

   Python 2.7.10?

   Note that although the installer is named "gatsby-cli", the command is "gatsby" (without the "-cli").
