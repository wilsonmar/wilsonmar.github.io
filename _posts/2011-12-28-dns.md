DNS (Domain Name Service)</h2>

	DNS servers obtain IP address from URL names by forwarding requests it cannot resolve from its own
	tables.
<p>
	Clients -- called <strong>resolvers</strong> -- make requests of DNS <strong>name servers</strong>.
	Two DNS servers are usually specified (in client machine TCP/IP properties) for load balancing
	and fault tolerance.
<p>
	DNS servers refer to 3 types of records to answer 3 types of queries:
<p>	<ul>
	<strong>A</strong> (host Address) records are used to answer <strong>forward lookup</strong> 
	of an FQDN (host name) to a specific IP address.
	The host name to IP address mappings for a zone are stored in the <strong>Domain.dns</strong> file
	in the <a href="1envvars.htm">&#37;systemroot&#37;</a>\System32\Dns folder.
<p>
	<a name="DNSPTR"></a>
	<strong>PTR</strong> (<span style="text-decoration:underline">P</span>oin<span style="text-decoration:underline">t</span>e<span style="text-decoration:underline">r</span> resource) records are used to 
	answer a <strong>reverse lookup</strong> of an IP address to a host name
	(another DNS domain name location).
	IP address to host name mappings are in the <tt><strong>z.y.w.x.in-addr.arpa</strong></tt> file.
	Create file <strong>1.0.0.127.in-addr.arpa</strong> zone file for reverse lookup.
<p>
	<strong>SRV</strong> (<span style="text-decoration:underline">S</span>e<span style="text-decoration:underline">rv</span>er location) records -- new in Windows 2000 DNS -- are used to
	<strong>locate domain controllers</strong>.
	SRV specifies the server to which a DNS name server <strong>forwards</strong> 
	when it cannot resolve a query.
	Windows 2000 server <strong>requires DNS</strong> to locate domain controllers.
	On Windows 2000, DNS is installed as a Windows component on a 
	domain controller with a static (not dynamic) IP address.
	</ul>
<p>
	Other types of resource records:
<p>	<ul>
		<strong>NS</strong> records notate which DNS servers are designated 
		as authoritative for the zone.
<p>
		<strong>SOA</strong> (Start Of Authority) records indicate the <strong>name of origin</strong> and other basic properties for each zone,
		including the name of the primary server for the source for information about the zone,
<p>
		<strong>CNAME</strong> (Cononical name) records define <strong>aliases</strong>.
<p>
		<strong>MX</strong> (<span style="text-decoration:underline">M</span>ail e<span style="text-decoration:underline">x</span>changer) records define the 
		owner and mail exchange server DNS name, 
		with <strong>preference number</strong>.
	</ul>
<p>
	There is a separate set of these DNSNode records for <strong>each DNSZone</strong> handled by a DNS server.
	DNS only resolves queries for zones to which it has <strong>authority</strong>.
	Zones are part of a hierarchial structure of 
	<a href="#TLDs">top-level domains<img src="http://merc.tv/img/itemsep.gif" width="11" height="11" border="0"></a>
	over <strong>Second-level domains</strong> (represented by the organization's name, such as Microsoft or Compaq),
	etc. 
<p>
	<table align="right" cellpadding="4" cellspacing="0" border="1"><thead>
	<tr><th> Standard </th><th> Active Directory Integrated </th></tr>
	<tr valign="top"><td> DNSZone </td><td> Container Objects </td></tr>
	<tr valign="top"><td> DNSNode </td><td> Leaf Objects </td></tr>
	</tbody></table>

	<strong>DNS zone</strong> data can be stored in <strong>text files</strong> on Primary or Secondary domain controllers.
	This is under the <strong>single master model</strong>.

	Alternately, you can change
	a Windows 2000 DNS service to use the <strong>Active Directory Integrated</strong> database.
	Replication of AD data to other servers makes this a <strong>multi-master</strong> model.
<p>
	This is done using the <strong>DNS Console Manager</strong> GUI -- 
	in a zone's Properties dialog box General tab, click the change button.
	Alternately, use a script to issue sub-commands from command interface
	<p><ul><tt><img src="http://merc.tv/img/cmd.gif"> nslookup.exe
	<br />Default Server: &nbsp; rns2.earthlink.net
	<br />Address: 207.217.77.82
	</tt></ul>
<p>
	AD Integration is reversed in the <strong>Advanced tab</strong> by setting the 
	&#8220;Load Data On Startup&#8221; field to &#8220;From Registry&#8221;.
<p>
	<img src="http://merc.tv/img/tool.gif" width="16" height="16" alt="tool" />
	Use the <strong>Windows 2000 Network Monitor</strong> to monitor and capture 
	packets sent to and from DNS servers.
<p>
	<img src="http://merc.tv/img/tool.gif" width="16" height="16" alt="tool" />
	DNS server administration can be done by a script using this utility from the Windows 2000 Server product CD:
	<p><ul><tt><img src="http://merc.tv/img/cmd.gif"> DNSCMD.EXE</tt></ul>
<p>
	Servers send an A (resource) record to DNS when it first boots up.
	To force a member server to register itself to DNS:
	<ul><tt><strong><img src="http://merc.tv/img/cmd.gif"> ipconfig /registerdns </strong></tt></ul>
<p>
	<img src="http://merc.tv/img/tool.gif" width="16" height="16" alt="tool" />
	In the <strong>Event Log</strong>, the DNS log file shows DNS request activities.
	But it doesn't show specific zone property changes
	or information about existing zone transfers.
<p>
	Caching-only DNS servers work from data cached while resolving queries 
	using server in <strong>Root Hints</strong> stored in the <strong>Cache.dns</strong> file 
	rather than from DNS zone transfers.


## Configuration

One no longer directly edit <tt>/etc/resolv.conf</tt>

On Ubuntu, within <tt>/etc/network/interfaces</tt>

<pre>dns-namservers 192.168.1.1. 8.8.8.8
dns-search example.com
</pre>

Reload network using <tt>/etc/init.d/networking reload</tt>

On Red Hat, write to <tt>/etc/sysconfig/network-scripts/ifcfg-eth0</tt>
